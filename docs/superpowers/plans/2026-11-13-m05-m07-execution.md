# M05~M07 운영 복원·장애 매트릭스·최종 증거 실행 계획

> 실행자: 기존 격리 worktree에서 executing-plans로 직접 구현하고, 전체 완료 후 fresh-context 검토1회를 수행한다.

**Goal:** 기존 맞춤 보고서·적재·성능 근거에 실제 기동/종료·정지 복원·F01~F16 반복 대조와 근거 검증/최종 문서를 완성한다.

**Architecture:** 기존 MySQL Outbox/Inbox·DB job·CDC·lease/PDF 경계를 유지한다. operations/restore 전용 Compose project·state·volume을 순차 기동하며 원본 portfolio를 보존한다. 정지 checkpoint는 별도 broker/connector와 복원 DB에서 Outbox snapshot 재전달을 허용하고 Inbox/job 상태로 중복 효과를 막는다.

**Tech Stack:** 기존 Java21/Spring3.5.9/Gradle8.14.3, 잠긴 MySQL/Redis/Kafka/Debezium 이미지, Python 표준 라이브러리·PowerShell bridge. 모든 실행은 Ubuntu다.

**Spec:** [설계](../specs/2026-11-02-portfolio-reliability-design.md), [M05 상세 범위](2026-11-13-m05-scope.md), [기존 M05~M07](2026-11-03-04-measurement.md), [프로토콜](2026-11-03-measurement-protocol.md).

## Global Constraints

- 사용자가 2026-11-13 M07까지 실행을 승인했다. 이전 M05 단독 범위/미착수 문구는 해당 시점 기록이며 이번 승인으로 M06/M07도 포함한다.
- 원본 checkout/자료·portfolio DB/828개 미확인 격리/volume/기존 offset/history 보존, 비밀/덤프는 비공개 state에만 기록한다. 새 시험 소유 자원만 정리한다.
- 현재 externally managed detached HEAD f6f41169f810eab66f791fb307d0e3e600ba06de와 기존 dirty 수정은 유지한다. 커밋·push·배포·포트폴리오PDF 편집은 제외한다.
- 정상복구 기본100건/경계대상1건·3seed·180초관찰, 과부하는 수락/거부 분리, F15는 CDC 선택으로 N/A. 실패/미실행은 통과로 만들지 않는다.
- 성능 개선율을 새로 약속하지 않고 과거 실측과 후속 수정의 지문/적용 범위를 구분한다. 기본 상태 cache-off를 유지한다.
